# reviews

该目录存放功能评审与验证记录。这里的写法不是建议，而是评审记录必须遵守的最小格式。

当前目录的正式角色分工如下：

- `Explore Agent`：只读补充事实与证据，不给最终通过结论。
- `Plan/Review Agent`：审查规格、计划、实现与测试覆盖，输出独立结论。
- `Verification Agent`：执行真实命令、记录真实输出并进行对抗式探测。

## 评审记录必须包含

- 评审对象与范围：明确本次评审的是哪个 current change 的 `proposal`、`specs/...`、`design`、`tasks`、plan、实现或测试产物。
- 评审角色：明确本次记录由哪类独立角色产出。
- 需求-测试映射：逐条列出需求点、对应测试、测试类型、证据位置与覆盖结果。
- 已覆盖内容：说明哪些需求点、边界或流程已经被验证。
- 未覆盖内容：说明哪些关键需求点、异常路径或边界仍未覆盖。
- 结构化结论：明确写出 `PASS / FAIL / PARTIAL`。
- 风险与漂移：明确写出剩余风险，以及是否发生需求漂移。
- 下一阶段判断：明确写出“是否允许进入下一阶段”和“是否需要用户确认”。

## 评审时必须核对的内容

### 1. 需求-测试映射必须先于结论

评审记录必须先核对需求点与测试之间的对应关系，再给出结论。没有映射表的评审记录视为不完整。

映射至少要写清楚：

- 需求编号或需求描述
- 对应测试用例、验证步骤或人工检查项
- 测试类型：单测、契约、E2E、人工验证或等价验证
- 证据位置：测试文件路径、用例编号、日志片段、截图、录屏或其他可追溯证据
- 覆盖结果：已覆盖、部分覆盖、未覆盖

### 2. 有关键需求未覆盖时，不得直接通过

如果存在未覆盖的关键需求点、关键异常路径、关键边界条件或测试矩阵缺项，评审结论不得写成通过、可合入或可进入下一阶段。

此时必须明确写出：

- 哪些内容未覆盖
- 为什么它们是关键缺口
- 需要补充哪些验证或文档

### 3. 结论必须固定包含结构化字段

每份评审结论都必须同时包含以下字段，且顺序保持一致：

- 结论：`PASS / FAIL / PARTIAL`
- 是否符合标准
- 已覆盖
- 未覆盖
- 剩余风险
- 是否发生需求漂移
- 是否允许进入下一阶段
- 需要用户确认的事项

如果任一项缺失，评审记录视为不合格。

### 4. 流程产物评审不能只看文件存在

对 proposal、specs、design、tasks、plan 等流程产物的评审，不能只写“文件已存在”或“文档已补齐”。必须进一步核对这些内容是否写清：

- 页面或模块边界
- 用户可见流程与分支
- 异常路径与回退条件
- 测试矩阵或验证映射
- 产物之间的约束关系是否一致

如果只是确认文件存在，而没有核对上述内容，评审记录不算完成。

### 5. 测试评审必须独立于实现评审

测试评审和实现评审必须分开记录、分开判断、分开给结论。

禁止以下写法：

- 用“代码看起来没问题”代替测试覆盖判断
- 用“测试都过了”代替实现评审
- 把实现正确性判断和测试完整性判断混写成一段结论

测试评审必须单独说明测试是否覆盖需求、是否覆盖异常路径、是否存在断言缩小或测试规避。

### 6. Verification 结论必须基于真实执行

`Verification Agent` 不得只根据代码阅读、测试名称或实现说明给出通过结论。

验证记录至少要写清：

- `Command run`
- `Output observed`
- 进行了哪些主动破坏或边界探测
- 最终 `VERDICT`

缺少真实命令或真实输出的 verification 记录，视为不合格。

### 7. 关键阶段不得绕过用户确认

当评审涉及以下任一场景时，记录中必须明确列出需要用户确认的事项，且在确认前不得写成“已进入下一阶段”：

- 规格批准后进入 `writing-plans`
- 计划批准后进入 `implementation`
- 需求漂移、范围变化或风险接受
- `verification` 后进入 `finish`

## 判定原则

- 功能正确但不符合规范，仍然视为不合格。
- 若发现降级实现、绕过流程或测试规避，必须要求回退修正。
- 若存在关键需求点未覆盖，不得写出通过结论。
- 若发现需求漂移、计划越权或规格缺口，必须中止推进并等待用户确认。
- 若 verification 缺少真实命令、真实输出或对抗式探测，不得写出 `PASS`。
- 评审结论必须能从映射表直接看出判断依据，不能只给风险摘要。
