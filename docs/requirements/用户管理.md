# 用户管理需求文档

## 1. 文档信息

**文档名称**：用户管理需求文档
**适用场景**：内部管理后台
**终端范围**：PC 后台
**目标用户**：管理员
**功能范围**：仅支持用户增删改查，不包含注册、登录、权限、角色、启用禁用等扩展能力

---

## 2. 项目背景

为满足内部后台对用户信息维护的基础需求，建设一个简单、清晰、可维护的用户管理模块。
该模块仅面向管理员使用，用于对用户基础信息进行录入、查询、修改、删除等操作，作为后续扩展角色权限、组织架构、账号体系的基础模块。

---

## 3. 建设目标

本模块目标如下：

1. 支持管理员快速新增用户信息
2. 支持管理员查询用户列表及用户详情
3. 支持管理员修改用户基础信息
4. 支持管理员删除用户
5. 删除采用逻辑删除，保证数据可追溯
6. 保持功能边界简单，当前阶段仅聚焦用户 CRUD

---

## 4. 功能范围

## 4.1 本期包含

1. 用户列表查询
2. 用户详情查看
3. 新增用户
4. 编辑用户
5. 删除用户（逻辑删除）
6. 条件搜索

## 4.2 本期不包含

1. 用户注册
2. 用户登录
3. 密码管理
4. 角色管理
5. 权限管理
6. 启用/禁用快捷操作
7. 批量导入导出
8. 批量删除
9. 审批流
10. 组织、部门、岗位关联

---

## 5. 业务对象定义

用户是系统中被管理员维护的一类基础数据对象，仅用于记录和展示用户信息。

### 5.1 用户字段

| 字段名  | 类型     | 是否必填 | 说明                             |
| ---- | ------ | ---: | ------------------------------ |
| 用户名  | 字符串    |    是 | 用户唯一标识名称，用于区分不同用户              |
| 姓名   | 字符串    |    是 | 用户真实姓名或展示姓名                    |
| 手机号  | 字符串    |    否 | 用户联系电话                         |
| 邮箱   | 字符串    |    否 | 用户邮箱地址                         |
| 状态   | 枚举/字符串 |    否 | 用户当前状态字段，仅作为基础信息维护，不提供独立状态管理流程 |
| 备注   | 字符串    |    否 | 补充说明                           |
| 创建时间 | 日期时间   | 系统生成 | 新建用户时自动记录                      |

### 5.2 状态字段说明

虽然用户字段中保留“状态”，但当前版本不做单独的“启用/禁用”管理能力。
“状态”仅作为用户基础信息的一部分，可在新增或编辑时填写或修改，不提供列表快捷切换、不提供专门状态变更流程。

---

## 6. 角色与权限范围

### 6.1 角色定义

当前仅有一种使用角色：

* **管理员**：可访问用户管理模块，并执行新增、查询、查看、编辑、删除操作

### 6.2 权限说明

本期不做角色权限系统。默认进入本模块的操作者均具备完整用户管理权限。

## 7. 页面与功能设计

## 7.1 页面结构

用户管理模块建议包含以下页面或交互区域：

1. 用户列表页
2. 新增用户弹窗或页面
3. 编辑用户弹窗或页面
4. 用户详情弹窗或页面
5. 删除确认弹窗

---

## 7.2 用户列表页

### 功能说明

用于展示当前未删除的用户记录，并支持按条件搜索和基础操作。

### 页面元素建议

#### 查询区

支持以下查询条件：

* 用户名
* 姓名
* 手机号
* 邮箱
* 状态

#### 操作区

支持以下按钮：

* 新增用户
* 查询
* 重置

#### 表格展示区

建议展示以下列：

* 用户名
* 姓名
* 手机号
* 邮箱
* 状态
* 备注
* 创建时间
* 操作

#### 每行操作

* 查看
* 编辑
* 删除

### 列表规则

1. 默认仅展示未逻辑删除的数据
2. 列表按创建时间倒序展示，最新创建的排在前面
3. 查询条件支持组合筛选
4. 点击重置后清空所有查询条件并恢复默认列表

---

## 7.3 新增用户

### 功能说明

管理员填写用户信息并保存，创建一条新的用户记录。

### 输入字段

* 用户名
* 姓名
* 手机号
* 邮箱
* 状态
* 备注

### 业务规则

1. 用户名必填
2. 姓名必填
3. 创建时间由系统自动生成
4. 保存成功后写入数据库
5. 新增成功后返回列表，并提示“新增成功”

### 校验规则建议

1. 用户名不能为空
2. 姓名不能为空
3. 用户名长度限制建议 2 到 50 个字符
4. 姓名长度限制建议 2 到 50 个字符
5. 手机号如填写，需满足手机号格式校验
6. 邮箱如填写，需满足邮箱格式校验
7. 备注长度建议不超过 200 字

### 用户名唯一性规则

建议用户名在未删除数据范围内保持唯一。
若新增时用户名已存在，则提示“用户名已存在”。

---

## 7.4 查看用户详情

### 功能说明

管理员可查看用户完整信息，但不可直接在详情页修改数据。

### 展示字段

* 用户名
* 姓名
* 手机号
* 邮箱
* 状态
* 备注
* 创建时间

### 规则

1. 详情页仅展示单个用户完整信息
2. 已删除用户原则上不在列表中出现，因此一般不可从前台直接查看其详情

---

## 7.5 编辑用户

### 功能说明

管理员可修改已有用户的基础信息。

### 可编辑字段

* 用户名
* 姓名
* 手机号
* 邮箱
* 状态
* 备注

### 不可编辑字段

* 创建时间

### 业务规则

1. 编辑时需回显原有数据
2. 保存前执行与新增一致的数据校验
3. 若用户名被修改，仍需校验唯一性
4. 编辑成功后返回列表，并提示“编辑成功”

---

## 7.6 删除用户

### 功能说明

管理员可删除用户记录，但删除方式为逻辑删除，不物理移除数据库数据。

### 删除交互

1. 点击“删除”按钮
2. 弹出二次确认框
3. 提示文案建议：`删除后该用户将不再显示在列表中，是否确认删除？`
4. 管理员确认后执行删除

### 删除规则

1. 删除采用逻辑删除
2. 被删除数据不在列表中展示
3. 删除不实际清除数据库记录
4. 删除成功后提示“删除成功”

---

## 8. 逻辑删除规则

为保证数据可追溯性，用户删除采用逻辑删除方案。

### 建议实现方式

数据库中增加逻辑删除标识字段，例如：

* `deleted`：是否删除，0=未删除，1=已删除

或：

* `is_deleted`：0=未删除，1=已删除

### 规则说明

1. 新增用户时，逻辑删除标识默认为未删除
2. 删除用户时，仅更新逻辑删除标识，不物理删除数据
3. 所有前台查询默认过滤已删除数据
4. 唯一性校验建议仅针对未删除数据生效

---

## 9. 业务规则汇总

1. 模块仅限管理员使用
2. 当前版本只做用户基础信息维护
3. 用户名、姓名为必填项
4. 用户名建议唯一
5. 删除采用逻辑删除
6. 创建时间系统自动生成，不允许手动编辑
7. 状态字段保留，但不做独立状态管理能力
8. 不提供批量操作
9. 不提供导入导出
10. 不提供权限与角色关联

## 10. 接口建议

以下为后端接口建议，便于前后端对齐。

### 10.1 查询用户列表

**方法**：`GET`
**路径**：`/api/users`

支持查询参数：

* `username`
* `name`
* `phone`
* `email`
* `status`
* `pageNum`
* `pageSize`

### 10.2 查看用户详情

**方法**：`GET`
**路径**：`/api/users/{id}`

### 10.3 新增用户

**方法**：`POST`
**路径**：`/api/users`

### 10.4 编辑用户

**方法**：`PUT`
**路径**：`/api/users/{id}`

### 10.5 删除用户

**方法**：`DELETE`
**路径**：`/api/users/{id}`

说明：删除为逻辑删除，对外仍使用删除语义接口。

## 11. 数据库表设计建议

表名建议：`sys_user`

### 字段建议

| 字段名        | 类型             | 说明               |
| ---------- | -------------- | ---------------- |
| id         | bigint         | 主键               |
| username   | varchar        | 用户名              |
| name       | varchar        | 姓名               |
| phone      | varchar        | 手机号              |
| email      | varchar        | 邮箱               |
| status     | varchar        | 状态               |
| remark     | varchar / text | 备注               |
| created_at | datetime       | 创建时间             |
| updated_at | datetime       | 更新时间             |
| deleted    | tinyint        | 逻辑删除标识，0未删除，1已删除 |

### 约束建议

1. 主键自增或雪花 ID
2. 用户名建立普通唯一约束需结合逻辑删除策略设计
3. 常用查询字段可增加索引，例如用户名、姓名、手机号

---

## 12. 非功能要求

### 12.1 易用性

1. 列表页操作路径清晰
2. 表单字段命名清晰
3. 错误提示明确，不使用模糊提示

### 12.2 性能

1. 用户列表支持分页
2. 单页默认建议每页 10 条或 20 条
3. 查询响应需满足后台基础使用要求

### 12.3 安全性

1. 当前仅假设管理员可访问
2. 前后端仍需保留基本参数校验
3. 删除操作必须二次确认

### 12.4 可维护性

1. 前后端字段命名保持一致
2. 删除、查询、校验逻辑统一封装
3. 为后续扩展角色权限预留字段和接口扩展空间

---

## 13. 验收标准

满足以下条件即视为本期需求验收通过：

1. 管理员可进入用户管理页面
2. 可查看用户列表，且支持分页展示
3. 可按用户名、姓名、手机号、邮箱、状态进行查询
4. 可新增用户，且必填字段校验生效
5. 可查看用户详情
6. 可编辑用户信息
7. 可删除用户，且删除为逻辑删除
8. 删除后用户不再显示于列表
9. 用户名重复时系统能正确拦截并提示
10. 创建时间由系统自动生成并正确展示
